# Windows port — status and handoff

Branch: **`windows-support`**. Goal: make superterm build and run natively on
Windows (in addition to the untouched GNU/Linux and macOS targets). This file
is the working log so the port can be resumed in a fresh session.

GNU/Linux and macOS behaviour must not change: every Windows change is behind
`{$IFDEF WINDOWS}` / `{$IFDEF UNIX}` or lives in a new Windows-only unit.

## Target and toolchain

- **Minimum OS: Windows 10 1809 (build 17763).** That is where the ConPTY API
  (`CreatePseudoConsole`) first ships. Nothing below it is supported.
- **Compiler on this machine:** FPC 3.2.2 win64 bundled with Lazarus at
  `D:\lazarus\fpc\3.2.2\bin\x86_64-win64\` (`fpc.exe`, and GNU `make.exe` 3.80).
- The POSIX `./configure` runs fine under git-bash and writes `Makefile`, but
  the bundled **GNU make is 3.80 and chokes on `else ifeq`** in `Makefile.in`
  (line 34). Until the Makefile is made 3.80-safe (or a newer make is used),
  build directly with fpc. The command that mirrors the release build:

```sh
export PATH="/d/lazarus/fpc/3.2.2/bin/x86_64-win64:$PATH"
# st_version.inc is generated by the Makefile; create it once by hand on Windows:
printf "const SUPERTERM_VERSION = '%s';\n" "$(cat VERSION)" > src/st_version.inc
mkdir -p build/units/win bin
fpc -Mobjfpc -Sh -vew -vm11030,11031 \
    -Fuvendor/fv322 -FUbuild/units/win -FEbin \
    -obin/superterm.exe src/superterm.lpr
```

To compile-check a single unit:

```sh
fpc -Mobjfpc -Sh -vw -Fuvendor/fv322 -FUbuild/units/win -o/dev/null src/<unit>.pas
```

> Bash-tool note: the working directory **persists between calls**; a stray
> `cd src` earlier will make later `src/...` paths fail. Prefer absolute paths
> or `cd /d/sources/superterm` at the top of each build command.

## Approach

- **`st_os.pas`** (new) — tiny cross-platform shim: `OsGetPid`, `OsGetPPid`,
  `OsRestrictFile` (chmod 600 on POSIX, no-op on Windows), `OsRestrictDir`
  (700). Units that only needed BaseUnix for pid + chmod now use this instead.
- **`st_conpty.pas`** (new) — the Windows PTY master (see below).
- Per-unit `{$IFDEF WINDOWS}` branches for the OS-facing code, keeping the
  POSIX path byte-for-byte under `{$IFDEF UNIX}`.

### Recurring gotchas (FPC 3.2.2 + Windows unit)

1. The `Windows` unit exports a WinAPI **`GetEnvironmentVariable(PChar;PChar;
   LongWord)`** that shadows the 1-arg `SysUtils` version. Any unit that uses
   both must call **`SysUtils.GetEnvironmentVariable(...)`** (qualified). Done
   in st_debug and st_video; watch for it in st_pty/st_server/st_fvui.
2. Several kernel32 calls are **absent from FPC 3.2.2's `Windows` unit** and
   are declared `external 'kernel32'` where used:
   - `GetActiveProcessorCount` (st_cpu)
   - `CreatePseudoConsole`, `ResizePseudoConsole`, `ClosePseudoConsole`,
     `InitializeProcThreadAttributeList`, `UpdateProcThreadAttribute`,
     `DeleteProcThreadAttributeList`, `CreateJobObjectW`,
     `SetInformationJobObject`, `AssignProcessToJobObject` (st_conpty)
   - `SetUnhandledExceptionFilter` (st_debug)
3. `STARTUPINFOEXW` and the job-object limit structs are not declared either;
   st_conpty declares its own.

## ConPTY backend — verified

`st_conpty.TConPty` was compiled and **run on this machine**: it created a
pseudo console, `CreateProcess`'d `cmd.exe /c echo SUPERTERM_CONPTY_OK && ver`,
and read the marker + Windows 10.0.26200 banner back through the output pipe
(exit 0). The probe program is in the session scratchpad
(`conpty_probe.lpr`) and is not committed. API surface:

- `Spawn(cmdline, cwd, cols, rows)`, `ReadOutput(buf, peekFirst)`,
  `WriteInput(s)`, `Resize(cols, rows)`, `Alive`, `ExitCode`, `Close`.
- Kill-on-close **Job Object** tears down the child tree (the Windows stand-in
  for `kill(-pgid)` in `TPty.KillPane`).
- `IsConPtyAvailable` reports whether the three entry points resolved, for a
  graceful message on pre-1809 hosts.
- **TODO in st_conpty:** merge `AExtraEnv` into a `CREATE_UNICODE_ENVIRONMENT`
  block (currently the child inherits the parent environment unchanged).

## Runtime TODOs (after it compiles)

- **Config paths:** `st_config.ConfigDir` and `st_artbg.ArtSearchPath` use
  `$HOME`. On Windows fall back to `%APPDATA%\superterm` (or `%USERPROFILE%`).
  A small `OsConfigHome` in st_os is the natural home for this.
- **Build:** either make `Makefile.in` GNU-make-3.80-safe (nest the `ifeq`
  instead of `else ifeq`) or add a Lazarus `.lpi`/`lazbuild` project for
  Windows (Lazarus is being installed on this machine).
- `sshpass` has no Windows equivalent; SSH panes should rely on keys/agent.
